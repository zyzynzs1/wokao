# 申论评分方案 v1（讨论稿）

> 状态：**待确认后执行**。本文件是评分体系重构的方案说明，尚未改动任何代码。
> 版本：grading-v2.0（讨论稿）  
> 日期：2026-10-27

## 0. 已达成共识

1. 采用**路线 B**：AI 建点 + 参考答案校准 + 逐点判定 + 代码算分 + 档位/区间/置信度。
2. 大作文采用**袁东累进四类文**作主判据，liuyuexi 的维度权重与档位上限作分数锚定和复核。
3. 输出必须同时包含：**档位、中心分、区间、置信度**。
4. AI 自命题：单独标记、降置信度、复核评分、命题自检。
5. 历史记录**重新处理**：先保存旧分，再按新标准重评，界面可对比。
6. 用户不具备人工打分能力：基准集采用**银标准**（由 AI 按本方案评分 + 多模型交叉 + 排序校验），不冒充官方金标准。

---

## 1. 总原则

1. **AI 判，代码算。** 模型只输出“覆盖状态、展开度、证据、档位证据”，不输出总分；所有算术在 TypeScript 中完成。
2. **材料优先。** 点池先由题干+材料独立构建，参考答案只做候选校准，不直接决定点池。
3. **可解释。** 每个得分/失分必须能追溯到：标准要点、材料出处、考生原句。
4. **可复现。** 点池生成后冻结；温度 0、关闭思考；评分标准与 prompt 版本化。
5. **诚实边界。** 没有任何公开官方逐点细则，最终分是“训练参考分”；必须展示区间与置信度，不声称“官方分”。
6. **不虚构分值。** 没有官方细则时，不宣称“某点占 X 分”；内部权重复一化后使用，界面只展示档位与经验校准分。

## 2. 评分设计（按题型）

### 2.1 小题：归纳概括 / 综合分析 / 提出对策

**输入**：题干、作答要求、给定材料、考生作答、点池（冻结）。

**步骤**：

1. **题干解析**：识别题型、作答对象、任务动词、字数上下限、是否有“分条/分类”要求。
2. **点池**：
   - 材料遍：逐段提取原子要点，绑定材料出处；
   - 校准遍（若有参考答案）：补漏（材料支持但答案没写）、合并（答案拆过碎的）、冲突标注（不强行消解）。
   - 点池冻结到 `pointPools.json`，后续复用；点池变更必须升版本。
3. **逐点判定**：每个可评分点输出：
   - 覆盖状态：`完整覆盖 / 部分覆盖 / 等义表达 / 未覆盖 / 超出材料`；
   - 展开度：`充分 / 基本 / 简略 / 仅列标题 / 未提及`；
   - 考生原句（命中必须有原句）；
   - 材料出处（标准要点对应句）。
4. **形式检查（代码）**：字数、分条、编号重复等（见 §3.4）。
5. **计算与定档**：见 §3。

**要点判定规则（硬约束）**：

- 措辞不同但意思到位 → 命中（等义表达）；
- 明确写出核心语义但缺少数字/对象/范围 → 部分覆盖，不得判未覆盖；
- 要点含多个可独立判定内容时，须全部写到才算完整覆盖；
- “不知道/不确定” → 按未覆盖处理；
- 归纳概括**不因缺少总括句扣分**；综合分析**缺总括句/点题句最多扣 1 分**（写作建议，不单独成点）；
- 不得用材料外常识补点，不得因未写材料未提及的内容扣分。

### 2.2 应用文（贯彻执行）

**评分结构** = 格式分 + 内容分 + 目的/场景分 + 语言语气分。

1. **格式要素按题干确定**（`required_format_elements`）：
   - 通常为标题、称谓、正文结构、落款、日期；
   - 题干明确不要求格式时，不得因缺标题/落款扣分；
   - 只对“题干要求的必需要素”扣分，且审题/评分/重评复用同一份清单。
2. **内容按板块赋分**：背景/目的、主要做法/成效、存在问题、下一步安排等；写到了相关内容即给板块分，**不逐词抠**。
3. **语言语气 / 目的场景**单列；不得因“内容不充实”重复扣格式分。
4. **形式检查**：字数、分条、格式要素；错别字不单独扣分（除非影响术语/语义）。

### 2.3 大作文（申发论述）

**主判据：袁东累进四类文**（不用小题采分点）：

| 档次 | 判据 | 35 分题分数区间（建议） |
|---|---|---|
| 四类文 | 跑题 | 0–11（中心 5–9） |
| 三类文 | 标题 + 开头（前+后）+ 总论点 + 分论点正确 | 12–17 |
| 二类文 | 三类文 + 开头、结尾写得好 | 18–24 |
| 一类文 | 二类文 + 分论点论证写得好 | 25–28（上限 28） |

> 40 分题按比例换算：四类 0–13、三类 ≤19、二类 ≤27、一类 ≤32。

**执行顺序（强制）**：

1. 判主题类型：单主题 / 双主题（AB 型 / ABC 型）/ 多主题；判文体：政论 / 策论 / 议论；
2. 判跑题（题干核心词与核心关系是否被覆盖；只“名义提及”限制三类文上限；完全偏题 → 四类）；
3. 按模板层次核对框架：标题、开头（前+后）、总论点、分论点；
4. 核对开头/结尾质量（决定二类）；
5. 核对分论点论证（决定一类）；
6. 应用硬规则（字数、抄材料、标题/分论点）与经验上限，给出档位 + 中心分 + 区间 + 置信度。

**辅助记录（只展示，不直接加总）**：立意扣题 20、材料运用 15、论证深度 25、结构 15、论据例证 10、语言 15（100 分制权重，用于诊断和档内定位）。

**硬规则（代码检查）**：

- 字数：低于要求下限 / 超过上限 → 在档内扣分并提示；严重不足（<50%）限档；
- 连续照抄材料 ≥20 字 → 记录并扣分；
- 标题未含题干主题词 → 二类上限；总论点/分论点缺关键词 → 档内下移；
- 模板化风险需与“针对性弱/材料支撑弱/论证断裂”同时出现才限制高档。

> 说明：字数与档位的具体阈值属于**训练规则**，不是官方标准，界面必须标注“非官方”。

## 3. 评分算法

### 3.1 点池与权重

- 可评分点（scorable point）必须满足：材料有据、可独立判定、直接回应任务、语义不重复。
- 默认**等权**：`w_i = 满分 / 可评分点数`。
- 不设“核心点固定几分”；核心/可选只在展示与审核中使用。
- 非独立点、可选点、背景/例子 → 不进入计分（仅作证据）。

### 3.2 逐点得分

```
单点得分 = w_i × 覆盖系数 × 展开系数
```

| 覆盖状态 | 覆盖系数 |
|---|---:|
| 完整覆盖 / 等义表达 | 1.0 |
| 部分覆盖 | 0.5 |
| 未覆盖 / 超出材料 | 0 |

| 展开度 | 展开系数 |
|---|---:|
| 充分 | 1.00 |
| 基本 | 0.85 |
| 简略 | 0.65 |
| 仅列标题 | 0.35 |
| 未提及 | 0 |

**权重倒置惩罚**：核心点若仅“简略提及”，展开系数再降至 0.7；仅“列标题”降至 0.5。

### 3.3 定档、中心分、区间

1. 计算原始分：`raw = Σ 单点得分 − 形式扣分`。
2. 计算得分率 `raw / 满分`，按阈值定档（小题/应用文）：

| 档位 | 得分率阈值 | 档位上限（占满分） |
|---|---:|---:|
| 一档 | ≥ 80% | 90% |
| 二档 | ≥ 60% | 75% |
| 三档 | ≥ 40% | 55% |
| 四档 | ≥ 20% | 35% |
| 五档 | < 20% | 15% |

3. 中心分 = `min(raw, 档位上限)`，按 **0.5 分四舍五入（round half up）**，夹在 `[0, 满分]`。
4. 区间 = 中心分 ± 满分 × 置信度比例（高 5% / 中 10% / 低 15%），夹在 `[0, 满分]`，按 0.5 取整。

> 说明：定档上限来自 liuyuexi 的经验校准，不是官方标准；界面显示“训练参考分”。

### 3.4 形式扣分（代码）

| 项目 | 规则（v1 训练规则） |
|---|---|
| 少字 | 每少 10% 扣 1 分，最多扣 3 分 |
| 超字 | 每超 10% 扣 1 分，最多扣 3 分 |
| 未分条（题干要求时） | 扣 1 分 |
| 编号重复 | 每处 0.5 分，最多 1.5 分 |
| 应用文格式要素缺失 | 每个必需要素扣 1 分（总分 20 分及以下）；25 分题每项 1.5 分；按满分比例可调 |
| 大作文抄材料 | 每处（连续 ≥20 字）扣 1 分，最多 3 分（并写入硬伤） |

### 3.5 置信度

| 置信度 | 条件 |
|---|---|
| 高 | 材料完整、题干清晰、有可信参考答案校准、两次判定一致（差异 ≤ 5% 满分） |
| 中 | 材料完整、无官方细则或无参考答案、单次判定 |
| 低 | AI 自命题、参考答案弱/冲突、点池争议、两次判定差异大 |

- 材料缺失/OCR 不清/题干不完整 → **不评分**，提示补齐。
- AI 自命题在正常置信度基础上**降一档**，区间加宽 5%。

### 3.6 复核

- 默认：同一模型用**另一套独立判点 prompt** 复核（不看第一次结果）；
- 若配置了第二服务商模型：用第二模型复核；
- 两次结果按点比对：不一致点重新判定一次；仍不一致 → 该点按“未覆盖”从严处理，并降置信度；
- 同答案两次评分中心分差 > 1 分 → 标记“建议重试/人工确认”。

## 4. AI 自命题的特殊处理

### 4.1 命题时自检（生成阶段）

生成后必须校验，不合格则拒绝/重生成：

- 题干任务明确，与题型一致；
- 材料完整，能支撑参考答案中的每个要点；
- 参考答案字数符合作答要求（不超过上限，不少于下限的 80%）；
- 采分点合计 = 满分；每题 4–6 个独立点（大作文不设采分点，给划档标准）；
- 难度/建议时长与题型匹配；
- 记录生成元数据：模型、prompt 版本、生成时间、校验结果。

### 4.2 评分时

- 点池**材料优先**构建，AI 参考答案只作候选校准；
- 强制复核（同模型独立 prompt 或第二模型）；
- 置信度降一档，区间加宽；
- 若“材料支持但参考答案没有”的点占比过高 → 标记“题目质量存疑”，该次评分不进入掌握度统计；
- 界面标注“AI 自命题 · 训练参考分”。

### 4.3 统计

- 首页掌握度 / 预测分：真题与 AI 题分开统计；AI 题默认只计入“练习次数”，不计入绝对分趋势；
- 可配置“包含 AI 题”开关。

## 6. 模块与流程

新增 `src/main/grading/`：

```
grading/
├── config.ts          版本、常数、阈值
├── constraints.ts     题干解析（正则 + LLM 兜底）
├── pointPool.ts       材料建点 + 参考答案校准 + 冻结缓存
├── judge.ts           逐点覆盖/展开判定 + 证据校验
├── application.ts     应用文板块与格式评分
├── essay.ts           大作文袁东累进四类文
├── rules.ts           形式/硬规则（字数、分条、抄材料等）
├── calc.ts            算分、定档、区间、置信度、取整
├── validators.ts      覆盖完整/证据/算术/档位校验
├── orchestrator.ts    gradeQuestion() 总流程
└── prompts/           各阶段 prompt + 版本号
```

主流程 `gradeQuestion(question, answer, options)`：

1. 题干解析 → 约束；
2. 取已冻结点池（无则建点并校准、冻结）；
3. 逐点判定（含复核 pass）；
4. 应用文/大作文分支评分；
5. 形式/硬规则扣分；
6. 算分、定档、区间、置信度；
7. 校验（覆盖完整、证据齐全、算术自洽）；
8. 返回 `GradeResultV2` + 兼容 `ScoreResult`。

IPC 变更：

- `records:submit` 内部改为调用 `gradeQuestion`；
- 新增 `grading:getPool`、`grading:rebuildPool`、`grading:grade`、`grading:reevaluateRecord`、`grading:migrationStatus`、`grading:runMigration`；
- 移除/停用 `App.tsx` 里启动自动重评逻辑，改为受控迁移。

移动端：在 `src/mobile/api.ts` 实现同一套新 API（AI 请求走 CapacitorHttp；点池存 localStorage；迁移同理）。

## 7. Prompt 草稿（实现时再细化）

### P1 题干解析

```text
你是申论命题与阅卷专家。只依据题干和作答要求，输出 JSON：
{
  "type": "归纳概括|综合分析|提出对策|应用文写作|文章论述",
  "task": "作答任务一句话",
  "constraints": {
    "minChars": number|null,
    "maxChars": number|null,
    "requireItems": boolean,
    "requiredFormat": ["标题","称谓","落款","日期"],  // 仅应用文
    "notes": "其他硬性要求"
  }
}
不得推断材料内容；看不清的要求写 null 并在 notes 说明。
```

### P2 材料点池（不看参考答案、不看考生答案）

```text
你是申论阅卷组负责制定评分要点的专家。只依据【题干】【作答要求】【给定材料】，
提取本题的“可独立判定的评分要点”，输出 JSON：

{
  "points": [
    {
      "text": "标准要点（可独立判定，尽量用材料原词或规范概括）",
      "group": "分组/考点，仅展示用",
      "evidence": "[材料X第Y段]：直接支撑该要点的原句",
      "independent": true
    }
  ]
}

规则：
1. 只从材料提取；不得使用材料外知识，不得写材料没有的内容。
2. 每个要点必须能单独回答“考生答到没有”；并列动作、动作+效果要拆开；
   同一动作的修饰语不拆；不得把背景、例子、宏观意义当独立要点。
3. 覆盖材料所有段落，但不要为凑数硬拆；通常 4–8 个核心要点（大作文不输出要点）。
4. 每条 evidence 必须是同一件事的材料原句；找不到依据就删掉该点。
5. 不设分值、不排序、不打分。
```

### P3 参考答案校准（有参考答案时）

```text
下面有【材料点池】和【参考答案】。参考答案是候选骨架，不是唯一标准。
请输出校准后的点池（JSON 同上，另加两个字段）：

{
  "points": [...],
  "addedFromMaterial": ["参考答案没写、但材料明确支持且能独立回答题干的要点"],
  "merged": ["参考答案拆得过碎、已合并的说明"],
  "conflicts": ["参考答案与材料冲突或无法核实的点，保留说明"]
}

规则：
1. 先补漏：材料支持、能独立回答题干的，即使参考答案没写也要加入；
2. 再合并：参考答案中同一功能被拆成多个标题的，合并为主点+展开；
3. 不得因参考答案措辞不同而删除材料支持的点；
4. 参考答案与材料冲突时保留争议，不强行纳入。
```

### P4 逐点判定

```text
你是申论阅卷专家。依据【题干】【给定材料】【要点表】【考生作答】，
逐条判定每个要点是否被答到，输出 JSON，不要计算总分：

{
  "judgments": [
    {
      "id": "要点编号",
      "status": "full|equivalent|partial|none|out_of_material",
      "expansion": "full|basic|brief|title|none",
      "userQuote": "考生原句（命中/部分时必须抄原文，未命中留空）",
      "note": "判定依据（可选）"
    }
  ]
}

规则：
- 措辞不同但核心意思到位 → full 或 equivalent；
- 明确写出核心语义但缺数字/对象/范围 → partial，不得判 none；
- 只写总括词、没有具体内容 → expansion=title；
- 要点要求多个独立内容时，缺一块即 partial/none；
- 命中必须引用考生原句；不得伪造引文；
- 不要新增要点，不要自己给分。
```

### P5 应用文板块/格式

```text
你是申论公文阅卷专家。依据【题干】【材料】【必备格式要素】【考生作答】输出 JSON：

{
  "format": [
    { "element": "标题", "status": "present|missing|wrong", "note": "" }
  ],
  "sections": [
    { "name": "背景/目的", "status": "full|partial|missing", "evidence": "考生原句" }
  ],
  "purposeFit": "好|一般|弱",
  "languageTone": "好|一般|弱",
  "notes": ""
}

规则：
- 只检查题干要求的格式要素；题干未要求的不扣分；
- 内容按板块整体判断，不逐词抠；
- 不得因内容不充实重复扣格式分。
```

### P6 大作文评阅（袁东累进四类文）

```text
你是申论大作文阅卷专家，按袁东“累进四类文”判档。只依据【题干】【材料】【作答要求】【考生作文】，
输出 JSON，不要计算总分：

{
  "topicType": "single|double|multi",
  "relationType": "AB|ABC|null",
  "essayStyle": "政论|策论|议论",
  "offTopic": false,
  "offTopicReason": "",
  "titleHasThemeWord": true,
  "structureCorrect": true,
  "openingEndingGood": false,
  "subArgumentEvidenceGood": false,
  "tier": "一类文|二类文|三类文|四类文",
  "tierReason": "逐条说明",
  "dimensionHints": {
    "立意扣题": "0-4 级证据说明",
    "材料运用": "...",
    "论证深度": "...",
    "结构": "...",
    "论据例证": "...",
    "语言": "..."
  },
  "hardIssues": [
    { "type": "字数|抄材料|标题|分论点|跑题", "detail": "具体位置与证据", "penalty": 0 }

判定顺序：
1. 判主题类型与 AB/ABC；2. 判跑题（四类）；3. 核标题/开头（前后）/总论点/分论点（三类）；
4. 开头结尾质量（二类）；5. 分论点论证（一类）；6. 输出硬伤与证据。

```

## 9. 基准集与校准（银标准）

由于你无法人工打分，采用以下协议：

### 9.1 数据

- 题目：选 8–12 道内置真题（覆盖 5 种题型 + 大作文），优先你练过的题；
- 答案样本（30–40 份）：
  - 真题参考答案（高锚点，预期不应得满分）；
  - 你现有的 12 条作答（真实样本）；
  - 由我改写的“好/中/差”变体（明确标注 synthetic，不冒充真人）。
- 每份样本由我按本方案逐份人工式评分（银标准），并记录档位、中心分、理由。

### 9.2 指标

- **绝对偏差**：AI 中心分与银标准中心分的平均绝对误差（MAE）；
- **方向性偏移**：AI 均分 − 银标准均分（整体偏高/偏低）；
- **区分度/排序**：高/中/差是否按预期排序（排序一致率）；
- **稳定性**：同答案两次中心分差；跨模型差。

### 9.3 校准

- 可调参数：部分覆盖系数（默认 0.5）、展开系数（1/0.85/0.65/0.35）、档位上限、形式扣分上限；
- 以最小 MAE + 排序一致率为目标，网格调整后冻结；
- 达到以下门槛才认为可用：|平均偏差| ≤ 满分 5%、MAE ≤ 满分 10%、排序一致率 ≥ 90%、同答案两次中心分差 ≤ 1 分。

### 9.4 说明

- 银标准不是官方金标准，只能证明“自洽、可校准、能区分”，不能证明“等于真实阅卷分”；
- 基准集脚本放在 `scripts/benchmark/`，可重跑；每次改 prompt/模型/常数都要回归。

## 12. 风险与边界

1. **绝对精度不可证**：无官方逐点细则；分数必然是经验校准值，必须展示区间/置信度。
2. **点池是最大偏差源**：必须冻结、可追溯、可人工修正（后续可在题目详情加“编辑评分点”）。
3. **API 成本/延迟**：每次评分约 4–7 次调用（建点仅首次；判点+复核+大作文）；使用 deepseek-flash 等低成本模型；移动端需提示等待。
4. **模型更新导致偏移**：prompt/模型/常数全部版本化；每次升级跑基准回归。
5. **AI 自命题**：评分只能作训练参考，不与真题同权；必要时用第二模型。
6. **许可**：liuyuexi 为 GPL-3.0、DDDTlight 为 AGPL-3.0；本方案为**独立重写实现**，不直接复制其代码/大段规则文本，只借鉴设计思想。
7. **数据兼容**：旧记录保留 legacy；同步协议不变（records 合并按 id 只增不覆盖，新字段自然携带）。
